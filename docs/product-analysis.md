# 产品分析：CC Agent Brain（v0.2 规划视角）

> 视角：产品经理。事实基础：仓库实际代码 + 2026 年公开行业资料（Mem0《State of AI Agent Memory 2026》、Graphlit 框架综述、Zep Graphiti 文档、claude-mem v13.8 发布资料、SQLite+sqlite-vec 本地方案实践）。资料检索时间：2026-09。

## 1. 产品定位

**一句话定位**：给编码 Agent 用的、本地优先、零依赖、可跨工具复用的「第二大脑」——自动捕获工作过程，沉淀为可检索、可审计的版本化记忆。

- 品类：AI Agent Memory Layer（Agent 记忆层），落在"编码助手增强"细分。
- 本质变化：v0.1 是"目录约定 + 提示词 + 轻钩子"的脚手架；v0.2 起是"带本地存储引擎的记忆产品"。
- 品类判断：2026 年记忆层已从"加分项"变成编码 Agent 的基础设施，且呈现三个确定趋势——**图/时序化、MCP 交付、可检视（inspectable）**。

## 2. 目标用户与 JTBD

| 用户 | 典型画像 | 核心任务（JTBD） | 付费/传播意愿 |
|------|----------|------------------|----------------|
| 重度编码 Agent 用户 | 每天用 Claude Code/Cursor 数小时，跨多个长期项目 | "换会话/换项目时别让我重新交代背景" | 高，是核心种子用户与传播者 |
| 隐私敏感的个人开发者/小团队 | 代码与业务信息不能上云 | "记忆能力要全本地、可读、可删" | 中，对"零云依赖"敏感 |
| 多工具切换者 | 同时用 Claude Code、Codex、Gemini CLI | "一套记忆喂给所有工具" | 高，MCP 跨工具是关键决策点 |

非目标用户：追求托管省心、愿意把数据交给云的团队（他们会选 Mem0 Cloud / Zep 托管版）。

## 3. 用户痛点（按频次×痛感排序）

1. 跨会话失忆：每次重新解释项目背景、决策来龙去脉（最高频）。
2. 记忆不可信：不知道 AI"记得"了什么、何时记的、新旧结论冲突时以谁为准。
3. 检索找不到：笔记越积越多，靠关键词/翻文件失效。
4. 被单一工具锁死：记忆存在某编辑器里，换工具即失忆。
5. 隐私顾虑：对话原文、密钥、业务细节被明文/上云。

## 4. 竞品格局与对标

| 方案 | 捕获 | 检索 | 记忆模型 | 交付形态 | 数据位置 | 对我们的启示 |
|------|------|------|----------|----------|----------|--------------|
| claude-mem（v13.8，80k+ stars 量级） | 全量自动+AI 压缩、回注 | 语义搜索 | 摘要库 | Claude Code 插件，npx 一键装 | 本地库/可选远端 | 证明需求与安装体验门槛；强绑 Claude 是其软肋 |
| Memory Plugin（marketplace 系） | 主动维护 | 文件/语义 | 记忆文件 | Agent Skills，跨多工具 | 本地+可同步 | 跨工具与 marketplace 分发是必选项 |
| Mem0（60k+ stars） | LLM 抽事实 | 向量+图+BM25 混合 | 事实+图 | SDK / 官方 MCP / 云 | 云或自托管 OpenMemory | 混合检索与 MCP 是行业标配 |
| Zep / Graphiti | 自动抽取实体关系 | 混合+图遍历 | 双时间知识图谱、事实失效 | 自托管/企业服务 | Neo4j 等 | 时序失效是"可信记忆"的正确方向，v0.2 已用关系型轻量实现 |
| 纯文件派（claude-memory 等） | 手动/半自动 | 直接读文件系统 | Markdown | skill | 纯本地 | 验证"人类可读、零依赖"有稳定受众，是我们的基本盘 |

结论：**中间存在明确空位**——"像纯文件派一样本地可读零依赖，但具备 Mem0/claude-mem 级别的自动捕获、真实检索与时序可信，并通过 MCP 跨工具"。v0.2 正在填这个空位。

## 5. 差异化与护城河

1. **零依赖本地引擎**：只用 Python 标准库（SQLite+FTS5），不需要 pip、Docker、API Key，中文 bigram 检索开箱即用——安装摩擦低于所有带向量库/图数据库的方案。
2. **Markdown 是投影不是牢笼**：底层结构化、顶层人类可读、可 Git 审计，兼顾机器检索与人的掌控感。
3. **时序可审计**：记忆用 supersede/expire 而非覆盖，能回答"上周我们相信什么、后来为什么改"。
4. **MCP 跨工具**：一份记忆服务所有 MCP 客户端，避开与 claude-mem 在单一插件市场的正面消耗。
5. **命名空间安全安装**：不覆盖 `.claude/`、可备份、可干净卸载，降低企业/谨慎用户的试用心理门槛。

护城河不是算法（检索能力会趋同），而是**"本地掌控感 × 跨工具可移植 × 可审计"的组合信任**。

## 7. 路线图建议

- **v0.2（本次）Local Engine**：事件流 + SQLite/FTS5 + 版本化记忆 + 审计 + MCP + 自动捕获闭环。
- **v0.3 Recall Quality**：可选本地 embedding（bge-small/e5，经 sqlite-vec），RRF 混合；内置 20–50 条时序/多跳/冲突小评测集，量化 recall@k（对齐 LoCoMo/LongMemEval 思路）。
- **v0.4 Portability**：官方 Marketplace/Agent Skills 打包、npx/uvx 一行装；记忆导入导出（JSON/Markdown）；全局记忆控制台。
- **v0.5 Optional Sync**：端到端加密的可选私有备份（默认仍纯本地）。

## 8. 成功指标

- 北极星：**周活跃项目中"自动召回被采纳"的次数/周**（记忆真正减少了重复解释）。
- 输入/健康指标：安装成功率；每项目日均捕获事件数；蒸馏记忆数与审计问题闭环率；检索零结果率；崩溃/降级次数（hook 不得阻塞用户）。
- 增长指标：Marketplace 安装量、MCP 跨工具接入数、README→安装转化率。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 与 claude-mem 等明星项目正面竞争被淹没 | 高 | 打差异：零依赖、可读、跨工具 MCP，不拼"AI 自动总结"花活 |
| Hook 机制随 Claude Code 版本变动 | 中 | 引擎与钩子解耦，MCP/CLI 可独立使用；补版本兼容测试 |
| FTS5 中文 bigram 召回/精度争议 | 中 | v0.3 本地向量补语义；先保证可解释、零依赖 |
| 用户不信任自动记忆 | 中 | timeline/audit/sync-md 让记忆完全可见、可改、可删 |
| 明文数据库泄露 | 中 | 捕获即脱敏 + gitignore；文档提示磁盘加密；v0.5 可选库加密 |
